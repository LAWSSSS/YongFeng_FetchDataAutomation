# 采集助手使用说明

在 Mac 上按日期查询质检、确认采集区间，再由采集助手把识别出的照片导入工作平台。网页里的日期和时间均为北京时间。

日常使用顺序是 **日期采集 → 视频确认 → 处理结果**。第一次使用，先在「设置」连接工作平台，再试着完成一条视频。

## 1. 下载并启动

适用于 **Apple 芯片 Mac（M 系列）和 macOS 14 或更新版本**。可以在苹果菜单的「关于本机」查看芯片和系统版本。

1. 用有仓库访问权限的 GitHub 账号登录，下载 Mac 完整版。完整包包含运行环境、视频工具和识别模型。 [下载 Mac 完整版 ZIP](https://github.com/zhaochengxiaohao-design/search_download_upload_auto/releases/download/v1.3.7/gather-assistant-1.3.7-macos-arm64.zip)
2. 在访达的「下载」文件夹双击 ZIP，把解压出来的 **采集助手-Mac-arm64** 整个文件夹移到「文稿」或其他可写位置。
3. 双击文件夹里的 **采集助手**。浏览器自动打开后，页面上方会显示 **日期采集、视频确认、处理结果、设置**。以后也可双击应用回到网页。

### 首次启动遇到 macOS 提示

首次打开时，macOS 可能提示「无法验证开发者」或「Apple 无法检查是否包含恶意软件」。确认 ZIP 来自可信的 GitHub 发布页后，打开 **系统设置 → 隐私与安全性**，找到采集助手，点击 **仍要打开**，按系统提示确认。公司管理的 Mac 若没有该按钮，请联系 IT。 [GitHub 发布页](https://github.com/zhaochengxiaohao-design/search_download_upload_auto/releases/tag/v1.3.7) · [Apple 的打开说明](https://support.apple.com/zh-cn/102445)

## 2. 连接工作平台

接入可以访问工作平台的网络。打开网页顶部的 **设置**，向下找到 **平台连接**，分别填入各平台的工作账号和密码，再点卡片上的连接按钮。

| 平台 | 用途 | 何时需要 |
| --- | --- | --- |
| **质检网站** | 查询日期范围内的质检记录 | 查询之前 |
| **采集平台** | 提交采集、播放和下载视频 | 提交采集之前 |
| **视觉AI平台** | 上传和导入识别照片 | 照片导入之前 |

看到对应卡片显示「已连接」即可继续。质检网站和采集平台可以勾选 **保存登录**，以后打开应用时会尝试自动连接。

## 3. 完成第一条视频

### 提交采集

1. 打开 **日期采集**，选择开始日期和结束日期，点 **查询待采集视频**。只查一天时，两个日期选同一天。
2. 在下方的「核对采集计划」看车牌、原始质检时间和拟采集区间。默认从质检开始后 **5 分钟**起，采集 **60 分钟**。时间需要调整时，点 **修改此条区间**，填好开始时间和时长，再点 **保存此条区间**。
3. 勾选要采集的记录，点 **确认采集所选**。第一次可以先勾选一条。批量操作可以用 **全选可采集**。页面下方的 **采集提交记录** 可以按提交日期展开，查看每批的提交情况。

### 查看、更正并确认视频

1. 打开 **视频确认**，展开提交日期，找到车牌，点击 **查看与更正 → 查看视频**。视频在当前卡片内打开，可以同时展开多条记录。若还在等待平台结果，等到「查看视频」出现再继续。
2. 需要改区间时，打开 **更正采集时间**，修改日期、开始时间或时长。时长可填 1–120 分钟。依次点 **核对修改** 和 **确认重新采集**，等新版可以播放后再检查。可以多次更正。
3. 区间合适时，在播放器下勾选 **我已查看并确认这一版视频**，再点 **确认最终区间并处理**。程序随后自动下载、识别、打包并导入照片。

更正错了，可以在最终确认前打开 **重试与版本操作 → 撤回本次更正**，等上一版恢复后再检查。如果确实要重做原区间，在同一处点 **按当前区间重新采集**。可以在 **历史版本** 查看之前的采集区间和可用版本。

### 查看照片处理结果

打开 **处理结果**，查看下载、识别、上传、导入和核验进度。照片导入并核验通过后，才会显示完成。记录有本地照片时，点 **查看结果图片** 可以打开对应照片包。

| 处理状态 | 含义 |
| --- | --- |
| **等待恢复** | 展开记录查看原因。磁盘、平台连接或文件占用恢复后，能自动继续的项目会接着处理。 |
| **需处理** | 展开记录，按提示核对指定的视频或连接。 |
| **可用部分已完成** | 已跳过损坏的位置，并核验可用部分生成的照片成果。 |
| **未检出目标／未找到可用画面** | 这次没有生成照片。具体原因在记录详情中。 |

关掉浏览器标签页后，应用仍在后台处理。处理期间让 Mac 保持开机，并连接所需网络和磁盘。

## 4. 文件保存、清理和更新

### 把工作区放到外置盘

默认文件保存在应用旁的 **数据 → 媒体**。视频、切片照片、压缩包和媒体缓存可以一起移到外置盘。

1. 接上外置盘，打开 **设置 → 本地数据**，点 **更改保存位置**。
2. 在访达选中外置盘或盘内的文件夹，按 **Option–Command–C** 复制完整路径，粘贴到网页。
3. 点 **预览迁移**，核对目标位置和文件数量，再点 **迁移并使用**。如果没有要迁移的文件，按钮显示 **使用此位置**。

程序会在所选位置建立 **视频工作区**，迁移已登记且能核实的文件。任务记录仍在应用旁的 **数据 → 系统**。要移回默认位置时，先接上原盘，再到同一处点 **恢复默认位置**。

### 清理完成的本地文件

在 **处理结果** 核对结束原因和照片成果，再点 **清理已结束文件**。弹窗会列出本次可清理的项目数和占用空间。确认后，程序会清理这些项目的本地视频、照片包和缓存。平台成果及任务历史会保留。

### 停止或升级应用

- **停止**。在程序文件夹里双击 **停止采集助手**。准备拔下外置盘或移动程序时，先停止后台。
- **升级**。先停止旧版并备份旁边的 **数据** 文件夹。把新版解压到一个新文件夹，将备份的 **数据** 复制到新版应用旁，然后打开新版。继续使用外置盘时，启动前先接上原盘。

## 5. 遇到问题时

| 现象 | 先做什么 |
| --- | --- |
| GitHub 下载显示 404 | 登录有此私有仓库访问权限的账号，再从发布页下载。 [GitHub 发布页](https://github.com/zhaochengxiaohao-design/search_download_upload_auto/releases/tag/v1.3.7) |
| 解压后看到「启动简易版.command」 | 这是源码包。日常使用请下载 **Mac 完整版 ZIP**，解压后双击「采集助手」。 |
| 浏览器没有打开 | 再双击「采集助手」。若弹窗给出以 `127.0.0.1` 开头的本机地址，把它粘贴到浏览器地址栏。 |
| 应用提示已损坏 | 从发布页重新下载 ZIP 并完整解压。如果提示仍出现，记录提示文字以便排查。 |
| 程序位置不可写 | 在访达把整个程序文件夹移到「文稿」等可写位置后再打开。已经使用过的应用先停止，再连同「数据」一起移动。 |
| 查询没有记录，或某条不能勾选 | 核对日期、质检网站连接和记录旁的原因。默认要求质检时长**超过 10 分钟**，并且有真实车牌或至少一张有效的智能判级照片。准入条件可在 **设置 → 采集设置** 查看。 |
| 提示已有采集 | 先查看提示关联的原记录。需要再次采集同一区间时，使用详情里的 **按当前区间重新采集**。 |
| 照片一直在排队 | 在 **设置 → 图片上传与导入** 查看是否暂停，再检查「视觉AI平台」的连接和照片数据集权限。 |

反馈问题时，请提供 **macOS 版本、点了哪个按钮、看到的提示文字**。如果启动提示查看日志，可在应用旁的 **数据 → 系统 → logs** 找到 `service.log`。分享截图或日志前，请去掉账号、密码和令牌。

## 从源码启动

源码版需要 Python 3.13 和 Node.js 22.13 或更新版本。在源码目录打开终端并运行 `zsh ./启动简易版.command`，停止时运行 `zsh ./启动简易版.command stop`。

源码版的照片识别还需要 Python 3.11、FFmpeg、ffprobe 和模型包。将模型 ZIP 放到源码目录，运行 `zsh ./启动简易版.command setup-models ./models-v1.zip`，再重启应用。 [下载 models-v1.zip](https://github.com/zhaochengxiaohao-design/search_download_upload_auto/releases/download/v1.3.7/models-v1.zip)
