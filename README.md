# 简易版质检视频采集

这是与原程序独立的本地网站，用于读取质检实绩、批量采集、人工更正、下载、上传核对，以及可选的模型识别与平台切片。视频采集时间由用户确认，不自动补采。简易版的数据库位于本目录 `data/collection.sqlite3`；首次启动为空，不迁入原程序的 53 条批次。

## 启动

双击 `启动简易版.command`，或在本目录运行 `npm start`。网页默认地址是 <http://127.0.0.1:8786/>，只监听本机。需要 Python 3.10+、Node.js 22.13+ 和 `ffprobe`；首次安装：

```bash
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock.txt
npm ci
npm run build
npm start
```

需要再换端口时，可运行 `PORT=8787 npm start`；开发网页代理也使用相同的 `PORT` 配置。

简易版与原程序分别登录两个网站。登录页默认勾选“长期保存到本机配置”；勾选后，账号和密码保存在 `~/Library/Application Support/InspectionVideoGatherSimple/credentials.json`，目录和文件权限分别为 700、600，供下次启动自动登录。取消勾选则只登录本次运行。该配置位于项目目录外。

## 使用

1. 登录质检网站与采集平台。按日期、每天的时间段、车牌查询实绩。
2. 查询结果按“已批准”和“未批准”分开显示数量，未批准项显示原因且不能勾选。可以全选已批准实绩，再核对所选采集时段。在“采集准入条件”中选择是否要求真实车牌、质检时长门槛、是否要求智能判级照片及最少张数，并选择车牌与照片任一满足或同时满足。“无”表示不要求该项，并非仅筛选没有该项的记录；时长始终必须严格超过所填分钟数。默认保留“真实车牌或至少一张有效智能判级照片，且质检时长严格超过 10 分钟”。初采固定为**质检开始时间 + 5 分钟，采集 60 分钟**；未识别车牌自动命名 `VIRTUAL_001` 等。

准入条件独立保存在本机数据库，重启后保留。“保存并应用准入条件”同时重新判定当前已查询的实绩，无需再次请求质检网站；源数据读取失败等问题仍保留未批准。修改草稿期间不能使用旧选择提交；其他页面改变设置后，旧查询和未提交预览会返回冲突，需要重新应用条件和预览。已提交批次、采集记录及后续手动更正继续使用各自提交时的规则快照，不受后续设置影响。旧记录没有规则快照时沿用原默认规则。

`GET /api/settings/admission` 返回已保存规则及修订号；`POST /api/settings/admission` 接受 `{rule, expectedRevision, searchId?}`，过期修订返回409。规则包含 `requireRealPlate`、`minInspectionMinutes`、`requireIntelligentPhotos`、`minPhotoCount` 和 `matchMode`（`any` / `all`）。照片只计智能判级的有效原图去重数量。
3. 核对每条任务后选择“仅采集”，或先设置保存目录再选择“确认采集并下载”。后者表示明确批准保存这些初采版本，平台完成后自动下载，无需逐条再次确认。下载意图与提交时目录按新批次持久化，重启继续等待；不会给旧批次自动安排下载，也不会再次启用已经取消的下载或覆盖手动更正。当前初采规则为质检开始后 5 分钟、采集 60 分钟，仅作用于新建预览；已有任务、已保存视频和手动更正不回算。程序按平台要求每批最多 20 条；相同相机和时段的已有任务会标为重复，不会自动认领原程序的任务。平台采集状态每 30 秒检查一次，也可手动检查。
4. 视频完成后在网页播放。满意原版可确认原版；若时间需要修改，在该记录内输入新日期、开始时间和时长，先核对草稿，再明确确认重新采集。允许连续更正两次或更多次，也可更正已提交且任务ID已确认的排队版本，无需先下载上一版。撤回最新更正会回到上一可用版本；旧版清理只处理比已确认版更早的版本。时长允许 1–120 分钟，精确到秒。
5. 在“视频查看与更正”设置最终文件夹。确认所看的版本后才会下载；勾选多条记录也可以批量安排下载，正在采集的条目会在平台完成后加入下载队列，待核对项会逐条拒绝。新版下载到本机并复制到最终文件夹后，才移除本程序绑定的旧版文件和云端任务、视频对象。清理失败会显示待核对，不会把旧版误报为已删除。

视频在本地网页中通过支持 Range 的代理直接读取平台结果，预览不另存副本。最多同时下载 5 条到本机独立 `data/work/` 暂存区并可断点续传；外置盘最多同时转存 5 条，与本机下载分别限流。转移直接写入目标目录，失败时保留已写入的临时文件，从记录的断点续接；复制和落盘等待分开计时，卡住的进程会退出并记录具体错误。复制成功后清理本机暂存副本，不执行外置盘回读或摘要校验。下载阶段仍检查平台响应、断点范围和内容长度。最终名称用结果 ID 避免冲突。切换保存目录只影响此后确认的视频。桌面 `视频抽帧` 源文件夹禁止用作最终目录。

若某次提交没有收到明确响应，程序使用提交前的任务 ID 清单核对新增任务；不能唯一确定时保留待核对，不按同名猜测或自动重发。更正尚未替换旧版时可撤回；提交结果不明且无法确认云端身份时会阻止危险的删除。新版已确认后需要再次更正，旧版会在下一版复制发布成功后清理。

“待核对”会显示具体原因和处理方法。重新核对只检查已绑定的任务和结果ID，事实恢复正常时解除异常，不修改用户填写的时段；任务不存在、平台失败或视频结果缺失时，可由用户点击“按当前更正区间重采”。多个结果或结果ID改变仍需人工核对。可以切换查看其他可用版本。

输入中的更正草稿保存在当前浏览器标签页的会话中，页面刷新会保留。其他操作改变版本时会保留输入并取消旧确认；查看最新采集区间后，再点击“核对修改”，会把原草稿绑定到当前显示的记录版本，随后可确认重新采集。确认仅提交刚核对的时段和版本；核对后若记录再次变化，需重新核对。同次确认重试沿用原请求ID。开始时间省略秒数时按 `:00` 处理。

采集记录按批次归类，每批默认只显示一条摘要，含北京时间、批次编号、记录数量与处理状态；展开后以独立卡片显示本批全部视频，电脑按宽度并排显示多列，手机单列。卡片直接展示当前版本，历史版本按需展开。可全选或下载本批可下载的当前版，待核对、已保存和已排队下载的条目不会被本批下载按钮重复选择。收起批次不会丢失更正草稿。日期、车牌、状态等筛选会同时作用于批次内容，摘要显示筛选条数与本批总数，批次操作仅处理当前筛选到的条目。

采集记录可按车牌或名称、原始质检或当前采集日期、状态和更正历史筛选。记录区的“已保存、可查看、下载中、等待平台结果”按钮点击即筛选，显示实时数量；状态下拉框与按钮同步，下载中包括已排队及正在写盘的版本。快捷状态保留已应用的其他筛选条件，车牌、日期和更正条件编辑后点击“查询记录”生效；切换筛选会清空批量选择。筛选后可单条或批量清除记录；每次都明确选择范围：仅网页记录与程序临时缓存，或同时清除本条绑定的云端任务、视频对象和已经下载的文件。全范围清理只使用保存的确切任务和结果 ID，并核对名称、相机、采集时段与文件版本；无法确认时保留可重试的记录。清理前后若又有新更正，过期选择会被拒绝。已经清除的记录不会在平台检查或重启后重新加入。

正在下载的单条视频可以停止并保留断点，之后可再次确认或重试。跨磁盘保存会先写入临时文件并原子发布，不执行发布后的回读校验；已存在的同名文件不会覆盖。质检网站的登录与采集平台下载互不阻塞。

## 上传核对

顶部的“上传核对”读取所选本机目录中的视频文件名和大小，与视觉AI平台两个数据集的导入日志分别比较：

- [27912 · 永锋车斗检测](http://pre-athena-mv.cisdigital.cn/#/dataset/27912?tab=base&namespace=1)
- [27944 · 永锋磁盘吊](http://pre-athena-mv.cisdigital.cn/#/dataset/27944?tab=base&namespace=1)

这两个数据集共用同一份本地视频清单。先在此页连接视觉AI平台，再填写视频目录并点击“读取目录并核对”。核对目录默认取当前下载目录，可以单独更改，支持包含子文件夹；隐藏缓存、符号链接、抽帧图片及未完成的 `.part` 等文件会被忽略。不存在的目录不会自动创建。

此连接与采集平台和 Edge 的会话独立；可将续期凭证保存在 macOS 钥匙串，下次启动自动恢复，不保存视觉AI账号密码。“读取目录并核对”只读取两个数据集的详情、任务分页和日志分页，不上传文件。核对只操作独立的报告表，不改变采集版本、人工更正和下载进度。自动上传须由下述“扫描并补传”明确添加队列。

任务列表请求限定为“数据集导入”（type=1）。服务端未按类型筛选时，程序仍只保留导入任务；日志读取入口再次校验类型。视频切片（21）、视频智能切片（22）、导出及其他任务均不读取日志，也不计入导入日志进度、运行中任务和上传判断。

核对以本地文件系统的创建时间（birth time）为起点，不使用文件名中的摄像头时间、修改时间或 inode 变更时间。任务列表完整分页读取后，只读取可能发生在文件创建之后的导入日志，显示实际读取和跳过数量；已经结束的老任务参考其创建和最后更新时间，仍在运行或日期不明的任务会保留核对。逐条日志再按发生时间过滤，每个视频使用自己的时间范围；某条缺失日志只阻止其可能时间范围内的文件，不阻止之后才创建的视频分类。无法获取文件创建时间时读取全量日志，时间不明或查询范围内缺失的日志仍需核对。文件创建时间会在页面与 CSV 中显示。

只有成功导入任务的日志记录才确认“已找到成功记录”。完整文件名保留车牌、时间和唯一尾缀；日志没有扩展名时，仅在本地名称唯一的情况下匹配，不按车牌或时间进行模糊匹配。运行中、失败、同名歧义、空文件及读取不完整的日志会显示“导入中”或“待核对”。“未见上传记录”表示完整读取的导入日志中没有相应成功记录；日志超过保留期或导入任务还没结束时，不把未匹配文件直接认定为未上传。

结果按两个数据集分别显示，可按名称、某一数据集的缺失项、两处缺失或待核对筛选，并复制文件名或导出 CSV。导出的是当前筛选的全部名单。报告保存在本地数据库，重新核对失败时保留上一份报告及其时间；原始日志、密码和会话令牌不写入报告。

“只缺磁盘吊”和“只缺车斗”仅包括另一处已确认上传、本处在相关日志中确认缺失的视频；“两处均未上传”不包含待核对项。这些名单与分类移动采用相同判断。旧核对报告必须重新读取后才能用于新分类计划，已有更正、完成移动及其本地路径保留。

“按上传状态移动视频”提供三个自选文件夹，默认使用原目录下的 `已上传`、`磁盘吊未上传` 和 `车斗未上传`。两个数据集都有成功导入记录的归入已上传；只有磁盘吊（27944）缺失的归入磁盘吊未上传，只有车斗（27912）缺失的归入车斗未上传；两处都未上传的留在原处。日志不完整、正在导入、来源已变化、旧报告缺少文件版本或目标重名的文件会保留并显示原因。点击“重新核对并预览分类”会先更新上传日志并递归读取全部分类文件夹，再生成预览；补传后可将未上传分类中的视频转入已上传，已在正确目录的单独计数。旧分类规则下未完成的计划必须重新生成预览，已完成的移动记录和文件位置保留。

先填写目标目录并生成预览，再点击“确认剪切”；移动范围是整份报告，不受结果筛选影响。重复分类会去掉原分类文件夹这一层，同时保留真实的子目录结构，例如 `磁盘吊未上传/日期/视频.mp4` 移至 `已上传/日期/视频.mp4`，不会产生嵌套分类文件夹；目标文件绝不覆盖。同磁盘直接重命名移动，跨磁盘先写入本计划的临时文件、校验并发布后再移除原文件，成功后原位置不留副本。移动完成会更新采集记录和上传队列中精确绑定的本地文件路径，更正版本与已完成的上传凭证保持不变；报告与 CSV 显示新位置。操作和每条进度写入独立日志表，中断后可点击继续，先核对已移动文件，再处理剩余项；同一确认请求不会重复移动。失败不会删除原片，无法确认的文件保留人工核对。桌面“视频抽帧”目录仍受保护。

## 自动上传与导入

在“上传核对”连接视觉AI平台后，点击“扫描并补传”。默认目录 `/Volumes/out/视频`，包含 `车斗未上传`、`磁盘吊未上传`、`已上传` 等分类子目录；只添加两个固定数据集各自缺少的完整视频。不会定期扫描新文件；后续新增视频需要再次点击扫描。同名歧义、不完整日志及无法确认的记录单列待核对，不自动批准。原片始终保留，不替用户删除或移动原视频。

队列在 Python 服务中运行，关闭网页不影响已入队任务。首次先在两个目标各上传、导入并核验一个真实视频；两个目标都通过后自动开启每目标最多4个独立上传进程。每批最多4条，单条不超过10 GiB，批次总量严格小于20 GiB。每目标最多一个导入任务，提交前重新查询已有任务，人工启动的未结束导入也会阻止新导入。导入期间可预上传下一批，每目标最多预备一批；两个目标独立推进。采用无标注、增量导入，保留已有标注。

每30秒检查一次。上传字节、已确认分片或真实阶段连续10分钟没有推进时，只停止该文件进程，核对完整对象后中止绑定的未完成分片。失败文件离开当前批次，其他成功文件可先导入。确认清理后分别间隔10、30、60秒单条自动重试，最多3次，之后等待人工重试。断网、授权失效、外置盘不可用暂停且不消耗重试次数。导入等待不使用10分钟上传超时，也不会终止平台导入。

对象和每个分片的凭证都写入独立的 `simple_upload_*` 表。上传完成响应丢失时先 HEAD 核验程序身份、文件版本和长度，再决定续传；不删除完整对象。导入提交前保存任务ID和视频ID快照、确切对象清单，响应不明时只对账；无法唯一确认会暂停该目标的新导入。页面“重新对账”不会重新发送导入。只有成功日志或新增的确切视频结果通过逐文件核验后才标为完成；部分失败只重试明确失败的文件，身份不明的留待核对。

暂停会停止本程序上传进程并保留确认分片；已提交的导入继续由平台执行、程序继续核对。服务重启后先对账再恢复上次启用的队列。视觉AI访问会话仅在内存中，保存连接后通过 macOS 钥匙串中的续期凭证自动恢复；续期失效时再在网页重新连接，已有队列与断点不丢失。临时授权经子进程标准输入传递，不写入队列、日志、环境变量或命令行；原始SDK异常、签名地址不入库。

平台临时授权可能只允许写入当次分配的目录。旧断点需要读取或续传原位置时，工作进程按需读取原站已有的运行连接配置；恢复客户端只允许访问本条确切对象和已绑定的分片ID，禁止删除完整对象、列举整个存储桶或操作其他视频。配置凭据仅在该工作进程内存中使用。旧位置没有完整对象且没有未确认分片时才允许重新创建；身份不明则保留待核对。

上传读取文件时，分类移动或清除同一文件会保留该文件并显示原因，其他文件可以继续操作；上传结束后可重试。已验证移动会同步队列路径和文件版本，不生成另一条上传。自动上传只清理本程序绑定的未完成分片，不清理其他上传、人工导入或本地原片。

依赖 Boto3（已加入锁定依赖）和 `ffprobe`。元数据检查不抽帧，不使用VLM或算法AI。Boto3按 [S3分片上传接口](https://docs.aws.amazon.com/boto3/latest/reference/services/s3/client/create_multipart_upload.html)执行，单进程每次只缓冲一个32 MiB分片。

本地接口（均不返回凭据、对象地址或原始日志）：

- `GET /api/uploads`：两个目标、队列、进度和异常。
- `POST /api/uploads/check-connection`：只检查上传授权结构与对象位置是否有效，只返回布尔结果和脱敏原因，不创建上传对象。
- `POST /api/uploads/scan`：`{directory, requestId}`，同请求幂等，重放不同目录返回409。
- `POST /api/uploads/pause`、`POST /api/uploads/resume`：暂停或继续已入队任务。
- `POST /api/uploads/{id}/retry`：单条重试；提交不明和结果不明的记录只重新对账。

上线前必须确认下载、发布、清理与分类移动均空闲，使用SQLite备份接口备份并校验数据库；空闲检查未通过则停止切换服务。测试使用独立临时目录、数据库、模拟Athena与本机S3协议服务，不访问真实平台。真实首条验收完成前保持每目标单条限制，不用测试文件污染数据集。

## 模型识别与一键切片

进入“模型识别与切片”，点击 **全部切片**。程序扫描两个视频集、读取21/22类切片日志去重、匹配本地文件、识别区间、提交并核验输出。再次点击只刷新并补充新视频，保留原批次、有效判断和既有任务；无需两类试切门槛。关闭网页不影响后端，服务重启后先对账再继续。默认一个本地分析进程，每个图片集最多一个平台切片任务；等待平台时继续分析后续视频。

视频目录、模型、工作程序和参数在折叠设置内修改。两个模型默认共用30秒抽样，同文件同位置只解码一次，分别送入模型。磁盘吊需要时细化到10秒，复用已有判断。图片只经过内存，模型阈值和定位检查不变。默认目标150张，可设100–200张，秒级间隔不小于1秒。缺少原片、截断、身份不明或模型不确定时仅该项进入“需处理”；临时抽帧故障最多自动重试两次，断网或断盘等待恢复。

每个物理文件一张卡片，分别展示车斗、磁盘吊、实际图片数及结果入口，可按名称、类别和状态筛选。默认开启自动归档：两类均结束，至少一类已核验图片，则剪切到“切片完成”；两类均未检出则剪切到“未检出目标”。缺失类别和真实异常保留原位。保留上传分类和子目录，例如 `视频/已上传/切片完成/日期/原文件.mp4`。分类目录以最近的分类移动计划为准，支持自定义名称。上传或识别占用文件时延后移动。

统一文件索引关联采集版本、上传和切片。所有受控移动同步绑定路径，原模型判断和已提交操作身份不随移动变化。归档使用持久化日志，同盘重命名，跨盘校验后移除源文件；重名或版本冲突不覆盖。失败可重试归档；桌面“视频抽帧”目录受保护。

新增接口：

- `POST /api/slicing/execute-all`：`{requestId, expectedRevision}`。请求可重放，过期修订409；扫描意图持久化，运行中点击在当前分析结束后刷新。
- `GET /api/slicing`：队列、整体阶段、归档状态和进度。
- `GET /api/files`、`POST /api/files/recheck`：文件索引及路径重查。
- `POST /api/files/{id}/archive-retry`：重试该文件归档。
- 原暂停、继续、单条重试、绑定和区间核对接口保留。已提交结果不明时只对账，不盲目重发。

模块职责：`slicing.py` 管理平台队列，`slicing_workflow.py` 管理一键意图与恢复，`slicing_analysis.py` 管理物理文件共用识别，`slicing_worker.py` 隔离模型推理，`slicing_remote.py` 封装平台，`file_index.py` 管理统一路径与归档日志。
