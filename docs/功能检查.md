# 功能检查与整理修复（2026-10-27）

本次保留采集版本、人工更正、断点、平台凭证及识别算法。已上传历史文件继续保留原位。

## 已修复

- 整理请求持久化，显示排队、运行、等待、完成和异常；无须移动时明确说明。
- 等待平台读取或文件占用只影响对应视频，不再以整批网络锁阻塞其他文件。
- 文件释放会唤醒整理；执行期间新请求不会丢失；重复点击复用已有整理操作。
- 文件移动凭证统一应用到采集、上传、切片和照片包。延迟回调不能写回旧路径，重启先恢复已确认的移动。
- 外置盘重连时，只有设备号变化且 inode、大小、修改时间和内容指纹全部一致才同步版本；旧的仅长度凭证不能掩盖内容变化。
- 目录索引合并同一已绑定文件的重复控制入口；不同文件不能仅凭名称或大小合并。
- 整理与平台清理分开调度；删除前重读当前绑定和资格，旧回调不能撤销已清理标记。
- 控制请求增加读取和操作超时；超时后按钮恢复，重试沿用请求编号。设置保存响应不明时先核对保存结果。
- 主入口统一为“整理视频”。旧位置变更失败仅在历史详情显示，不再提供无效的旧迁移重试。
- 移除整批“检查平台状态”按钮，保留自动更新与单视频核对；没有可继续项目时禁用“继续”。

## 可用部分归入已保存

- 当前版本的两类切片处理结束，产生的照片全部完成上传和导入核验后，自动出现在“已保存”筛选中，标记“已保存（可用部分）”。原片的损坏状态仍保留，不生成或批准替代视频。
- 可手动点击“全选已完成可用部分 → 归类到已保存”。批量接口 `/api/videos/bulk-classify-saved` 逐条检查版本、修订号及结果凭证；不完整或已更正的条目保持原状。请求重放不重复启动任何处理。
- 旧客户端的 `status=complete` 仍可读取可用部分子集；新网页统一使用“已保存”，不再重复显示“已完成”分类。
- 增量验证：548 项后端、39 项前端测试通过，类型检查与构建通过；隔离网页已验证全选、归类及已保存筛选。

## 界面合并与交互检查

- 状态仅保留一组筛选按钮；日期与更正条件收进折叠区。名称草稿和状态一起应用，避免页面条件与实际查询不一致。
- 批量入口统一为“选择范围 → 全选”：当前筛选结果、可下载当前版、已完成可用部分。选择后才显示适用的下载、归类和清除操作。
- 下载说明与下载进程合并；切片页只显示一处识别进程及图片队列。删除固定的抽样/图片数横幅，以实际设置为准。
- 原片查看和绑定不再在每个类别下重复。空操作菜单隐藏，更正时间与重试操作分别命名。
- 修复：已选条目的修订变化后取消过期选择，不再自动批准新修订；单视频及全局按钮加即时互斥。
- 修复：延迟轮询不能覆盖新操作状态；区间及路径草稿按修订和处理代次保留，各类别独立。
- 修复：某个状态接口失败时保留其他已读取的数据；切换栏目清除上个栏目的旧提示。
- 首次读取期间明确显示加载状态，不再把尚未读取的数据显示为“没有采集记录”或引导重复登录。
- 548 项后端、43 项前端测试通过，类型检查与构建通过。隔离网页验证了部分读取失败、组合筛选、批量范围、归类及 390px 排版。
- 本轮仅更新前端及测试，无须重启后端；识别算法、模型阈值、人工更正和后台队列均保持原样。
