# 视频工作区

在网页顶部展开“文件工作区”，填写一个父目录，点“预览整理”。确认预览后点“启用并整理”。原有进程数量仍在切片页调整，模型与判断规则不变。

程序创建 `视频工作区`，遇到其他同名目录自动选择带序号的名称。再次选择本程序工作区会复用，避免嵌套。

```text
视频工作区/
├── 采集视频/视频名/原视频.mp4
├── 未切片/视频名/原视频.mp4
├── 车斗未切片/视频名/原视频.mp4
├── 磁盘吊未切片/视频名/原视频.mp4
├── 已切片/视频名/原视频.mp4
├── 车斗已切片/视频名/图片/… + 压缩包.zip
├── 磁盘吊已切片/视频名/图片/… + 压缩包.zip
├── .处理中/
├── .缓存/
└── .处理记录/
```

原视频只保留一份。下载进入“采集视频”，加入切片后进入“未切片”。车斗导入核验完成后进入“磁盘吊未切片”，反向同理；两类结束后进入“已切片”。照片和压缩包核验前在“.处理中”，完成后进入类别结果分支。同名不同版本使用稳定短编号区分文件夹，文件名保留。

启用后，下载、核对、自动上传和切片共用这些路径。扫描只读取五个原视频分支。旧的独立目录写入接口返回409，不能把配置再次分散。上传状态只显示在网页，不创建交叉分类目录。

整理前备份数据库到程序的 `data/backups`，等待写入和文件占用释放。按逐文件日志迁移；跨盘校验内容后再移除源文件，冲突不覆盖。重复请求复用原操作，修改位置带配置版本。原始创建时间独立保存，移动后仍用于上传日志查询。主数据库留在程序数据目录，断盘仍可查看历史。

自动清理要求同版本原片在27912和27944都有确切导入凭证与结果ID，并再次核对原片存在；两类均结束，产生的图片全部核验完成。单纯同名、成功日志或“已完成”标签不能授权删除。未检出目标和恢复流程确认无可切片片段保留真实原因，仍须满足原片凭证条件。网络、磁盘、模型或身份问题保留文件。

清理仅删除已登记且版本相同的原片、照片、压缩包，等待播放和上传释放占用，逐文件记录进度。云端成果、历史、更正和观察不删除。已清理的历史不会重新抽帧或下载。未知文件、模型目录、桌面“视频抽帧”不迁移或递归清理。

已按用户要求保留的已上传历史视频及其现有结果不参与工作区迁移和本地清理，正在进行的切片和图片导入继续。保留操作基于当时已完成上传记录或绑定的平台视频ID及本地文件版本保存快照；不以同名文件代替版本，也不自动将未来新视频加入历史保留名单。断盘恢复、重新扫描和重启后仍生效。保存保留规则会使旧整理预览失效，必须重新预览。

接口：`GET /api/workspace`；`POST /api/workspace/preview`；`POST /api/workspace/{预览ID}/apply`；`POST /api/workspace/{预览ID}/retry`；`POST /api/workspace/reconcile`。预览和操作使用请求ID，配置冲突返回409。`apply` 的 `pilot=true` 仅供首条真实验收：处理一个凭证完整的原片，余下文件需重新预览并应用，避免首条验证时提前启动全量整理。

`POST /api/workspace/preserve-uploaded` 保存当时已上传视频的保留快照，操作幂等并备份数据库；`POST /api/workspace/{预览ID}/cancel` 真正取消预览，刷新页面不会重新出现。
