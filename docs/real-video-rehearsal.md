# 真实视频隔离演练

此入口供开发验收使用，不启动或更新日常网站，不读取保存的登录凭据。
质检、采集、下载和照片导入使用隔离协议适配器；视频解码、模型识别、
JPEG/ZIP 导出及 Boto3 子进程是真实实现。原视频上传继续停用。

## 运行

准备一个只含模型、工具和抽样参数的 JSON，字段参见
`scripts/run_real_video_e2e.py` 中的 `ALLOW_SETTINGS`。不填写平台账号、
密码、密钥或生产数据库路径。模型必须为现有部署包，不能通过修改阈值
制造成功结果。

```sh
.venv/bin/python -B scripts/run_real_video_e2e.py \
  --source '/完整路径/原片.mp4' \
  --settings '/完整路径/模型设置.json' \
  --root 'data/test-runs/唯一运行编号'
```

复测切片、上传及整理的意外恢复时增加 `--photo-faults`。完整真实识别链
会依次遇到一次分片断流、完成响应丢失及导入提交响应丢失，分别对账，
验证不重复导入；两类照片核验后才整理。新报告只根据实际状态和断言
生成，不复用上轮失败结论或手动推进结果。

需要本项目的后端依赖、现有 Python 3.11 推理环境、FFmpeg、FFprobe，
以及足够保存三个无重编码采集版本的空间。源码不附视频、模型或账号。
入口针对已确认的约 75 分钟「鲁NH1113」样本：模拟请求截取原片中的
0–60、5–65、10–70 分钟，采集时间规则沿用当前的开始时间加 5 分钟。

工具首次计算原片 SHA-256 并只读复制，结束后再次检查原片身份和哈希。
中途恢复必须使用同一原片和设置；已经完成的检查点不会重复创建。
所有可写产物仅在新的运行目录中。

## 输出与判定

- `capture-result.json`：质检、准入、提交、更正、历史下载、续传及清理。
- `natural-progress.jsonl` / `natural-latest.json`：真实模型和照片流水线进度。
- `natural-result.json`：真实标签、区间、照片数和模拟导入凭证。
- `transport-result.json`：真实 ZIP 的分片上传及导入故障契约。
- `tcp-result.json`：真实 loopback HTTP 传送完整原片，16 MiB 断开 socket 后准确续传。
- `fault-result.json`：真实媒体故障与独立契约，逐项标注边界。
- `source-after.json`：受保护原片的最终完整性。

`no_target`、真实待核对和调度阻塞如实保留。故障成功指正确拒绝、等待、
恢复或转人工，不要求故障变成完成。已知缺陷探针可能正常通过 pytest，
但它证明的是缺陷仍可复现，不能计为业务验收通过。

若保留失败现场后需要验证下游节点，可显式使用 `--resume-category bed`
或 `magnet`。这是**后端诊断推进**：直接执行未改动的业务节点，保留
另一类别成果、真实观察和失败现场，不代表网页恢复按钮可用，也不把
自动基线改判成功。

模型没有自然命中的分支使用同片真实照片执行独立传输契约，不能冒充
该类别模型识别成功。没有两个视频集的精确原片备份凭证时，保留测试
原片属于正确行为；清理成功分支仅作用于隔离契约的测试文件。

默认保留检查点以便诊断；全部所需节点结束后加 `--clean-media`，工具
仅清理写入器明确登记的测试文件。无注册清单不授权删除，不按扩展名
扫描删除邻近文件。清理保留报告和诊断；清理后的媒体不能原位重放，
下次完整演练使用新的运行目录。

## 小测试与浏览器

```sh
.venv/bin/python -B -m pytest -q \
  tests/test_real_video_capture.py tests/test_real_video_platform.py \
  tests/test_real_video_scheduler_probe.py
```

`tests/real_video_faults.py` 提供可复用的故障入口。浏览器验证按
[界面验收](ui-validation.md)操作，仅连接独立样例端口；真实视频交互使用
[独立模拟站](interactive-rehearsal.md)，上传及导入锁定关闭。
桌面和窄屏截图、JUnit、节点 JSON 是诊断资料，不进入 Git。

演练后按明确文件清单清理本次生成的视频、照片、ZIP 和分片对象，保留
报告、脱敏证据和必要数据库检查点。不得递归清理用户原片或未知目录。
