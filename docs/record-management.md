# 记录与操作

日期采集、视频确认、处理结果按实际提交日期分组，默认折叠。同日不同提交保留各自身份。无确切提交日期时显示“日期未记录”，不从文件名猜测。

卡片默认显示名称、时间、状态和一个详情入口。更正、播放、历史版本、区间及照片结果位于展开区域；模型与目录路径不需要用户填写。终态不显示进度条，上传100%仍需等待导入核验。

视频确认详情在当前卡片内展开，一次只打开一条；桌面三列、中屏两列、窄屏一列。后台刷新保留播放器与草稿。处理结果从最终确认后开始显示下载阶段，本地照片工作使用真实确认日期分组；平台已有的提交日期保留。

点击“批量管理”后显示选择范围、全选、结束选择及删除操作。筛选或记录版本变化时移除失效选择；日期组操作只作用于当时明确的范围。取消更正草稿继续保留。

## 删除规则

已结束且凭证完整的记录先安全清理绑定本地文件，再隐藏记录；未结束记录仅从网页移除。其他有效记录仍引用的文件保留。云端成果不删除，后台保存不能使隐藏记录重新出现。删除不提供恢复入口。

`POST /api/records/delete` 接收请求编号和每条记录的类型、ID、修订号，立即返回 `202 + operationId`。`GET /api/record-operations/{id}` 返回逐条处理结果。重复请求复用同一操作；执行中记录改变时保留该条，其他条目继续。旧删除入口在受管理模式下共用此队列，旧恢复接口返回410。

## 确认与更正

用户可以多次修改采集区间，查看并确认最终版本后才进入下载及照片处理。接口带修订号和请求编号；旧版回调不覆盖新版。查看详情不会更改采集区间。

下载并行数量在设置中管理（1–8），历史保存也占用同一下载名额。历史版本保存在统一媒体目录，通过准确的任务和结果凭证续传，不更改当前版本的确认或更正。已有本地文件优先用于播放；历史下载保持独立记录及文件版本。

照片导出、上传和两个目标的导入独立运行；完成需核对实际图片、唯一ID、数量及任务归属。有效片段处理完成可归入终态，原视频仍保留真实的不完整标记。
