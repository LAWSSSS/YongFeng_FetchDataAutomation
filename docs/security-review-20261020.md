## 已修复

| 问题 | 修复 |
| --- | --- |
| 图片压缩包使用 `image/`，平台显示导入结束却无图片 | 按原站无标注示例使用 `images/`。旧错误包可手动修复容器并重传，JPEG 字节不变，旧任务与对象凭证保留 |
| 两个后台循环都可提交同一个切片包 | 切片包使用单独调度器和互斥锁。提交前保存任务、图片清单；响应不明先对账 |
| 导入核验只查前五页，按名称包含关系接受少量无关图片 | 使用名称前缀查询并验证完整分页、任务类型、目标、对象清单；全部预期图片须有明确任务关联或提交前后差集 |
| 包上传没有完整保存分片创建意图和已确认分片 | 持久化创建、分片、完成意图，恢复时复用确切对象。无新字节的重复心跳不计进展；断网和断盘不消耗重试次数 |
| 暂停后包上传仍继续，暂停期间的查询可能接着提交 | 暂停状态持久化，停止该程序的上传进程；网络查询返回后再次检查暂停状态。已提交平台任务保留 |
| 分类移动仅按文件名回写；两类压缩包同名会冲突 | 按实际绑定文件分组，按确切记录 ID 和源路径更新，保留类别目录。采用预览快照、请求 ID、持久化移动日志和跨盘校验 |
| 同名、同大小文件可导致源文件被删除 | 移除启动时隐式移动；移动不覆盖，路径拒绝符号链接和受保护目录。清理前核对整个删除集合及文件版本，只删登记的照片 |
| 删除展示记录会删除任务凭证，重启又重新出现 | 展示日志独立隐藏；采集历史软删除，保留去重与结果关联凭证；列表查询不回写数据库 |
| 双模型只显示来源类别，包状态长期停留在排队 | 同一文件显示两类结果，按各类别状态筛选，实时同步包状态、任务、图片核验数及异常入口 |
| 改动分类目录后还能确认旧预览；多页设置互相覆盖 | 目录编辑使预览失效；设置草稿绑定编辑时的修订号，冲突保留草稿。按钮防重复，网络失败显示可处理错误 |
| 本地网页可能被其他网站嵌入或跨站调用 | 保留本机 Host/Origin 校验，增加 Fetch Metadata 检查、禁止嵌入及内容安全策略 |

## 算法与依赖

抽样、识别、模型文件、预处理、阈值、区间选择均保持原样。车斗 180 张、磁盘吊 150 张的默认值及已有设置未改动。`slicing_core.py`、`slicing_worker.py`、`slicing_analysis.py`、`magnet_export.py` 未修改；`slice_export.py` 仅改压缩包内部目录。

推理依赖升级为 PyTorch 2.14.1、Pillow 13.0.0，并提供完整锁定清单。原环境与独立升级环境在同一视频的 19 个位置、双模型共 38 次判断中，标签及分数完全一致；这是抽样验证，不代表穷尽所有输入。

安全依据：[PyTorch checkpoint 公告](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p)、[Pillow 安全说明](https://pillow.readthedocs.io/en/stable/handbook/security.html)。模型部署包仍是可信本地代码，不接受来源不明的模型。
